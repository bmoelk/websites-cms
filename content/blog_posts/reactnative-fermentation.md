First Day of Chain React 2017

![](https://cdn-images-1.medium.com/max/1024/1*3FtiqPlA6byleo6ng4SK5g.jpeg)

I’ve been paying attention to the Infinite Red folks since RubyMotion’s #Inspect conference in 2014. They’ve been pioneers/early adopters with a focus on mobile development technologies for a while. I watched their [transition](http://community.rubymotion.com/t/so-react-native-impacts-on-rubymotion/1363/2) [to React Native](https://medium.com/@ReactAmsterdam/speaker-interview-gant-laborde-88c3b47ac076) as Node.js, React and Facebook have all emerged as technical leaders in our industry. So I’m excited to be at their React Native conference and to visit Portland for the first time.

<h4>Doubt is Healthy</h4>

The first day of ChainReact has reiterated a few givens:

- Mobile is the way most people experience the Internet
- Native mobile development provides the best UX

But what is not obvious, is the development path forward; even at Chain React.

This first poll on a *very-cool-I-wanna-win-a-drone* RN app called [The Jump](http://thejump.com/) asks “**Do you think RN is ready for large/complex apps?**” is indicative of some of the lingering doubt about moving up the technology stack.

[Brent Vatne](https://medium.com/u/d5a707474bd2) called us out to start building shit with all the tooling we have. I could NOT agree more. He also quoted Rich Hickey and reminded us that not everything is awesome. OTOH, TIL Portland’s [RubyJewel Ice Cream Sandwiches](http://www.rubyjewel.com/ice-cream-sandwiches-flavors/dark-chocolate-cookie-with-fresh-mint/) are, indeed, certifiably 1000% awesome.

![](https://cdn-images-1.medium.com/max/855/1*LQdB98Xf9hKZDktft5Gc3A.jpeg)

I think this doubt is good. We should be discriminating, we should be critical. AND those things are not mutually exclusive of being kind, encouraging, and constructive. Based on the attendees, I think the React Native community gets this.

<h4>Mobile Development isn’t even a teenager</h4>

Modern mobile development hasn’t existed for very long. The iPhone is barely 10 years old and its App Store was introduced in June 2008. We’ve seen [many](https://phonegap.com/) [development](https://www.appcelerator.com/) [stacks](http://www.rubymotion.com/) in a very short amount of time. The pace of tooling change has been brisk to say the least.

Perhaps I’m showing my age, but I still believe writing solid software takes time, even if you stand on the shoulders of giants. In my opinion, most software really matures around version 3 and takes a few years to bake completely.

This is my way of saying, RN is young and I’m going to use it anyway. It’s easy to forget historical context and while we need to make decisions today, it‘s useful to adjust our expectations accordingly.

<h4>Less Opinionated is better in the Long Run</h4>

[Javier Cuevas](https://medium.com/u/525387bd48ce) asserted that RN is difficult for beginners because it is not very opinionated: There is no set file structure, no standard for how to generate your app, libraries focus on one thing and one thing only, etc. He gave this example “Since Redux is just a data store library, it has no direct opinion on how your project should be structured.”

I agree; it is harder for beginners. However, I think it’s also better for developers in the long run. For example, Windows vs. Linux, Rails vs. Phoenix, etc.

So React Native, keep doing you…[create-react-native-app](https://github.com/react-community/create-react-native-app) and [Infinite Red’s Ignite](https://github.com/infinitered/ignite) will bridge the gap.

<h4>Final Thoughts</h4>

I think React Native is a winner. The combination of elements and confluence of industry events have set it up nicely. I’m excited for day 2 of Chain React and to build a few mobile apps using RN in 2017.
